Digital Brolly Voice Agent

Operator Guide & Build Report
Prepared 1 September 2026 · Telugu / Tinglish outbound calling · Sarvam voice backend
What this system does It reads leads from your Google Sheet, calls each one in Telugu (or Tinglish, Hindi, English), either delivers a message and hangs up (one-way) or holds a conversation about the courses (two-way), and writes the transcript and outcome back to the Sheet. Every call opens with an AI disclosure, respects DND, and uses the registered 140-series caller ID.

Part 1 — Operator guide

1.1 Starting the system

Everything runs in Docker. From the project folder:

docker compose up -d --build

This starts five services:

ServiceWhat it isWhere
backendThe calling engine (FastAPI). Dials, talks, records, syncs the Sheet.http://localhost:8091
consoleThe web console you operate from.http://localhost:3200
cloudflaredThe public tunnel Plivo uses to reach the backend during a call.automatic
redisThe call queue. Safe to flush; everything rebuilds from the database.internal
postgresThe database — the single source of truth for leads, campaigns and calls.internal
After changing code, always rebuild docker compose restart and --force-recreate silently keep running the old image. Only docker compose up -d --build picks up code changes. Changes to .env do apply on a plain restart.
If calls ring and drop the moment they are answered — the tunnel died Cloudflare quick tunnels get torn down without warning; cloudflared stays "Up" serving a dead hostname, and Readiness shows "PUBLIC_BASE_URL … is unreachable (ConnectError)" for every campaign at once. Fix: 
docker compose restart cloudflared
That is all — the backend asks the tunnel for its new hostname by itself before every dial batch (happened 1 Sep, 19:35 IST; recovered this way). The permanent fix is a named Cloudflare tunnel on your own domain (fixed hostname, needs a Cloudflare account): set TUNNEL_TOKEN and PUBLIC_BASE_URL in .env.

Open the console and check the Readiness strip at the top of the home page. Every item must be green before you dial. It checks the Plivo number, the tunnel, the Sarvam key, the database, Redis, and — for two-way Telugu — that the feature flag is on.

1.2 Preparing the Google Sheet

The Sheet is connected through the Apps Script already deployed against it (the /exec URL in .env). The backend reads leads from a tab named Leads every 10 minutes, and writes transcripts to a tab named Transcripts.

The Leads tab did not exist — this is why no lead was ever called from the Sheet Until 1 September the Sheet had no Leads tab. The script answered a missing tab exactly like an empty one, so the backend reported "synced 0, no error" every ten minutes for weeks. Create the tab as below, then apply the one-line script patch in section 2.2 so this can never be silent again.

Create a worksheet named exactly Leads. Row 1 is the header:

1.3 Creating a campaign

Console → Campaigns → New campaign. Three choices matter, and none of them can be changed by the AI during a call:

SettingOptionsWhat it decides
Languagete Telugu · tinglish Telugu+English · hi · hinglish · en · auto Which voice engine runs. Telugu and Tinglish use Sarvam (Indian voices, Indian telephony STT). Hindi/English/Hinglish use ElevenLabs. ElevenLabs cannot speak Telugu at all — this is not configurable.
Modeoneway · twoway One-way: speaks the script and hangs up; the lead's voice is never listened to. Two-way: a real conversation — the lead asks about fees, duration, batches, and the agent answers from your course documents. When unsure, choose two-way.
ScriptEnglish text Required for one-way. Written in English; the system renders it into natural Telugu once per campaign. For two-way it is optional — leave it blank and the agent opens with a standard greeting in the campaign's register (Telugu, or Tinglish with course fees, batch timings, placement in English) and takes questions.

The AI disclosure is enforced automatically. If a script lacks one, the system prepends "ఇది డిజిటల్ బ్రోలీ నుండి ఏఐ ద్వారా చేసే ఆటోమేటెడ్ కాల్" and logs a warning; after every call it re-checks what was actually spoken.

1.5 Launching and watching calls

  1. Campaign is Active (toggle on the campaign page).
  2. Leads are pending with valid consent.
  3. The scheduler dials automatically every minute during calling hours. Press Dial now on the campaign page to start immediately.

Watch progress on Calls. Each row shows the lead, status, duration and turn count; click through for the full transcript.

Lead statusMeaning
pendingWaiting to be dialled.
queued / callingPicked up by the dialer / on the phone right now.
doneCall completed. Transcript stored.
failedNot connected (no answer, busy, network). Retried up to max attempts (default 2).
dndOn the Do-Not-Disturb registry. Never dialled.
Calling hours are set fully open (00:00–24:00) on the owner's instruction India's TCCCPR generally restricts promotional calls to about 09:00–21:00, and penalties attach to the Plivo number and its DLT registration — a blacklisted number stops every campaign at once. Restoring a 10:00–19:00 window is one line in .env (CALLING_HOURS_START / CALLING_HOURS_END) and a restart.

1.6 Reading results

  • Console → Calls: the authoritative record. Transcript, duration, turns, outcome, and the Summary — an outcome tag plus what the lead said, e.g. "Interested — asked the BDCP fee, wants batch timings."
  • Sheet → Transcripts tab: a copy of every transcript, written within 30 minutes of the call. On the Leads tab, Status becomes the call result and Notes becomes that same summary, for the matching phone number.
  • Test on a handset, not a speakerphone in a room. Background voices and echo trigger the recogniser; the noise gate now filters most of it, but a quiet handset is what a real lead sounds like.
  • Test-call checklist for a two-way Telugu call to your own number:
    1. Say "ఓకే" mid-conversation — the call must continue.
    2. Ask a fee question — the agent must answer from the documents, not promise a callback.
    3. Say "బై" — the call must end with a spoken goodbye.

1.7 Stopping

To…Do
Stop one campaignToggle it Inactive. Calls in progress finish; nothing new is dialled.
Stop everything nowdocker compose stop backend. Leads mid-call are released back to pending automatically.
Never call a number againLeads → the lead → Do not call.

1.8 Daily checklist

  1. Readiness strip all green.
  2. Settings → Sheets sync: last sync recent, no error, dialable > 0.
  3. Campaign active, script correct, mode correct.
  4. One test call to your own number before real leads.
  5. Check the log for [compliance] — any ERROR there is a stop-dialling event.

1.9 Five-minute demo

Two campaigns are ready and inactive, each with one lead (your own number, consent recorded): Demo - Telugu two-way and Demo - Tinglish two-way. Nothing dials until you switch one on.

  1. Home page: Readiness strip all green.
  2. Campaigns → tick Include inactive (inactive campaigns are hidden by default) → Demo - Telugu two-way → toggle Active → Dial now. Your phone rings within seconds.
  3. Answer on a handset. Say "ఓకే" (the call continues), ask "కోర్సు ఫీజు ఎంత?" (answered from the documents), say "బై" (farewell, then hang-up).
  4. Calls page: the row appears with duration, turns and the Summary line. Click through for the transcript.
  5. Toggle the campaign Inactive again. Repeat with the Tinglish one to hear the difference: course fees, batch timings, placement in English.
  6. Settings: Sheets sync status — shows what the Sheet integration reports (needs the Leads tab, §1.2).

Part 2 — Build report, 1 September 2026

2.1 What was found broken

#ProblemEvidence
1The Sheet fed no leads /admin/sheets-status reported synced 0, error null every 10 minutes. The container log held the real cause: update_lead error: 'Leads sheet not found.' The spreadsheet had no Leads tab, and the script reported a missing tab exactly like an empty one.
2The last word of sentences was deleted A guard that strips unpronounceable scripts (Armenian, Hindi) judged whole words by every character. The Telugu sentence mark । was not on its allowed list, so ఉన్నాయి। became nothing. The codebase's own sentence splitter treats । as normal — the two rules contradicted each other. This was the "words breaking in the middle" you heard.
3Calls hung up on "okay" The model called end_call when the lead said "ఆ ఓకే" — agreement, not goodbye.
4One-way calls mispronounced names Transcripts show నమస్తే Mouli గారు — the English spelling reached the Telugu voice. The fix existed only on the two-way path.
5Consent column collision A sheet with only a "Consent At" column matched it as the consent basis too, filing a date where "explicit" belongs — leads permanently undialable, nothing logged. The CSV importer already guarded this; the Sheet path did not.
6Sync reported the wrong number It counted rows written, not rows the dialer would call. With no consent columns those are "40" and "0" — and it showed 40.
7No manual sync The only trigger was the 10-minute timer. After fixing a sheet, you waited to find out.
8Campaign names matched exactly "demo class" in the Sheet did not match "Demo Class" in the console — row silently skipped.
9Sheet leads dialled last They carried no dial order, so every uploaded lead was called before any Sheet lead.
10Tinglish contradicted itself (fixed, rows 14–16) Tinglish differs from Telugu by one instruction ("keep course, fees, batch… in English"), but three later rules order the model to reply in Telugu script and to spell course, fees, placement in Telugu. Tinglish two-way has never been run: 2 campaigns, 1 lead, one-way only.

14Tinglish prompt no longer contradicts itself. The OUTPUT FORMAT, TELUGU SPELLING and UNCLEAR SPEECH rules and both script framings are now chosen by register: for Tinglish they no longer demand "Telugu script" or mandate Telugu spellings for course, fees, placement. Pure Telugu is unchanged. The register is read back off the style text with languages.is_code_mixed() — exact match against the catalogue, so a placeholder or a missing style is always pure Telugu. app/languages.py, app/telephony/sarvam_prompts.py
15A Tinglish opening. Scriptless two-way calls had one Telugu constant for both registers. DEFAULT_TWOWAY_TINGLISH keeps the identical disclosure sentence (ఆటోమేటెడ్ కాల్, never a Latin "AI") and then "మా digital marketing courses గురించి… Course fees, batch timings, placement…". Chosen per call by default_twoway_opening(). sarvam_prompts.py, sarvam_bridge.py
17Noise gate on the lead's audio. Sarvam's "speech started" signal fires on any sound and was the agent's only interrupt signal, so a cough, a TV or a second person cut the agent off mid-sentence exactly like the lead's voice, and the recogniser even produced fake sentences from room noise. A "speech started" now counts only after 200 ms of audio at ≥ 1.5× the quiet level measured just before it (never below an absolute minimum); a transcript from a sound the gate measured as non-speech is dropped, but anything it could not measure passes through — ignoring a real lead is the worse failure. Every decision is logged as noise gate: with its numbers; all thresholds are .env knobs; SARVAM_NOISE_GATE_ENABLED=false restores the old behaviour. Real interruptions now land ~200 ms later. The floor is the quietest 200 ms of recent non-speech audio, not the average — on the rehearsal call the average was inflated by the agent's own echo on the handset and a real question was dropped once. app/telephony/sarvam_stt.py, app/config.py
18A summary for every call. Sarvam calls never had one — the console's Summary column was blank and the Sheet's Notes said "N turns". After each call the model now writes a two-line English note from the transcript: an outcome tag (Interested / Not interested / Callback / No answer / Unclear) and what the lead asked or said, e.g. "Callback — asked the BDCP fee (₹50,000), wants a call tomorrow." Written after the call outcome, never delaying it; a one-way call gets "One-way message delivered."; it uses only the transcript and is told never to invent a fact or price. app/telephony/call_summary.py, call_routes.py, sheets/writeback.py
16Tests on the real catalogue text. The Sarvam prompt tests had used hand-written placeholder styles, which is why the contradiction survived. 15 new tests use languages.style("tinglish") / ("te") directly and assert each register's prompt is internally consistent. tests/unit/test_sarvam_prompts.py, test_sarvam_bridge.py, test_languages.py
Three deliberate non-changes in the Tinglish work
  • Speech recognition stays pinned to te-IN for both registers. Sarvam auto-detection mis-hears Telugu as Croatian/Urdu; the register lives in the prompt, not the transport, and te/tinglish must share one backend switch (_TELUGU_TOKENS) or preflight breaks.
  • The short canned lines — farewell, "say that again", "one moment", the disclosure prefix — stay in Telugu. A Hyderabad Tinglish speaker says every one of them exactly so, and the disclosure prefix must stay in Telugu for compliance.
  • "SEO" is still spoken as ఎస్ఈఓ in both registers: an acronym is pronounced by its letter names in any language, and Latin "SEO" would be read by the synthesiser as a word.

with

  • Danda bug: proven with the exact deployed regex — ఉన్నాయి।, ఉంటుంది॥, ఫీజు… all DROPPED before, all kept after; Armenian and Hindi still dropped.
  • Manual sync exercised live against the backend: {"synced":0,"received":0,"dialable":0,"error":null} — correct until the tab exists.
  • Console container exercised live: serves the page and proxies to the backend with auth through the compose network.
  • Rehearsal call, 1 Sep 20:23 IST (19 turns, 2 min 55 s, handset): fee, course list, topics, offline option and the fee breakdown all answered from the documents; "batch details" honestly declined (not in the documents); clean ending on "ఓకే థాంక్యూ".   • Tinglish two-way proven on a live call, 1 Sep 17:01 IST (9 turns, 49 s): the opening was spoken exactly as designed — …మా digital marketing courses గురించి కాల్ చేస్తున్నాను.
